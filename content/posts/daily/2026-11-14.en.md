CapLite fixes its planned writes before reading tool results; in AgentDojo’s simulated benchmark under the main attack it records zero successful attacks across 13,935 tool-goal episodes on 15 models [1]. That zero does not cover attacks that only contaminate the final answer, and the paper shows an unprotected example [1].

**Item 1: When a small model can write a faulty security policy, can code directly check what the agent is authorized to do?**

Background: The study compares enforcement defenses against prompt injection. Some have the agent’s model generate a program, privilege policy or tool-dependency graph for code to enforce; on the tested models, faulty artifacts can admit attacks or prevent normal tasks from running [1]. (General explanation added by this site: prompt injection hides instructions in data such as emails or web pages to redirect an agent; a write is an action that changes external state, such as sending a message, modifying an object or transferring money.)

Zimo Xu, Wenzhuo Liu and Hideki Nakayama submitted “CapLite: Prompt-Injection Defense for Small Language Model Agents without Model-Written Security Artifacts” on 2026-11-12 (UTC). Its planner sees only the user’s request and tool documentation before fixing its planned writes. Code derives authorization rules from tool names, documentation and parameter schemas, then checks that authority values such as recipients, amounts, objects and destinations are explicitly stated in the request or confirmed by the user. Later tool results cannot append writes; missing authority values prompt a confirmation request [1].

Why it matters: The main attack is AgentDojo’s important_instructions. Across 15 open-weight models, each running 929 episodes whose attack goal needs a tool call, CapLite records 0 successful attacks out of 13,935. Task utility uses a different population: 949 attacked pairs per model. Averaged across the 15 models, task success under attack is 29.0% for CapLite, 27.2% for CaMeL and 50.2% for the undefended agent [1]. (General explanation added by this site: open-weight models have publicly released parameters; task success measures completion of the user’s task, whereas attack success measures achievement of the attacker’s goal.)

Mean usage per episode is 17.1 thousand tokens for CapLite and 93.7 thousand for CaMeL. This counts prompt and completion tokens over each model’s 97 benign tasks and 949 attacked episodes; it is not an attacked-only average or an actual monetary bill [1]. (General explanation added by this site: a token is a unit of text processed by a model.)

Where it sticks: The guarantee trusts the user’s request, tools and their documentation, and constrains the write sequence and authority values such as recipients and amounts. Free text such as message bodies, temporal values and the final answer do not have the same protection. The main attack metric excludes 20 pairs whose goal is only to add a sentence to the final answer, and the appendix shows CapLite repeating the attack sentence in such a case [1]. All results come from AgentDojo’s four simulated suites, with no real users, accounts or data. Confirmation requests receive no reply in the experiment and count as task failures [1].

What to watch next: this is our own point to watch, not a conclusion of the paper: whether other teams using request-grounded checks on different toolsets or real tasks can report unauthorized execution, user-task completion, confirmation requests and total token use together, while separately counting contamination of the final answer.

**Item 2: After an agent has found a good program, can it select it without reliable validation labels?**

Background: AgentSSL casts semi-supervised learning as program search: an agent receives a small labeled set and a larger unlabeled set, then generates, executes and revises learning programs. The authors evaluate discovering good programs separately from selecting one from the candidate pool [2]. (General explanation added by this site: semi-supervised learning uses limited labeled data together with a larger unlabeled set; a label is a sample’s known class or answer.)

Ethan Lin, Akanksha Sarkar, Ziang Liu, Kristin Branson and Jennifer J. Sun submitted “AgentSSL: Can MLE Agents Leverage Unlabeled Data?” on 2026-11-12 (UTC). The agent searches with noisy validation feedback or unsupervised metrics. The image-classification experiments restrict it to the same CLIP ViT-B-16 and DINOv2-B backbones, adaptation library and data splits as the human baselines. Search time is allocated according to the corresponding baselines’ compute cost [2]. (General explanation added by this site: a backbone is the base network providing a model’s main feature extraction; fine-tuning continues training an existing model for a task.)

Why it matters: Table 1 covers six datasets with two labeled-examples-per-class settings each, for 12 settings, evaluated on three random splits. When the best discovered program is chosen after the fact by mean test accuracy, agent results beat the best human baseline in 8 settings. The largest gap is on RETINO with 40 labeled examples per class: the best program found with noisy validation feedback reaches 72.47%, against 50.66% for the strongest human comparator in that cell, supervised learning. The table directly reports a 21.81-percentage-point advantage [2]. This is the best candidate identified with knowledge of test performance; selecting a program in practice is a separate problem.

Table 2 measures the accuracy lost when the feedback score selects a program instead of the test-best program in that candidate pool, averaged across random seeds. For noisy-validation AgentSSL on RETINO with 80 labels per class, the table gives −47.29: this denotes a 47.29-percentage-point accuracy gap between the selected program and the pool’s best [2]. The authors also provide ProgramSelectBench with 16,977 pre-evaluated program instances from human baselines and agent solutions; different training splits of the same implementation count separately [2].

{{< industry-link item="2" industry="ai" side="cost" inference="different allocations of a limited label budget reduce actual annotation bills for machine-learning services" >}}The source studies allocating limited labels between training and program selection [2], which relates to data-annotation inputs for machine-learning services; it does not thereby measure actual annotation bills.{{< /industry-link >}}

Where it sticks: The paper treats reliable selection as an open bottleneck. In its ecology cases, AgentSL without unlabeled data performs comparably to AgentSSL; both agents have high variance on BuckTales and fall below the full-data expert baseline. These results do not establish that unlabeled data always add a benefit or that a real deployment has already cut costs. The authors also warn that generating more programs may widen the gap between the pool’s best and what label-free selection chooses [2].

What to watch next: this is our own point to watch, not a conclusion of the paper: whether new program-search systems report the after-the-fact best result, the result chosen by an actual selection method and the label budget together, so discovery ability and usable outcomes can each be checked.
