Three studies examine how models use timestamps to align events, how generated images affect visual answers, and which code edits are needed to pass task tests. All three preprints were first submitted to arXiv on November 25, 2026 (UTC). This issue draws on metadata and the authors’ abstracts.

## Pre-aligned events make timestamp use hard to assess

Tingrui Huang and colleagues altered time information and event-to-series alignment in 310 questions across two tasks. The authors report that accuracy could remain high when timestamps were replaced with relative offsets or removed, while breaking the alignment between events and the series caused systematic failures. Models made little use of timestamps when the inputs already matched events to the series. [Authors’ abstract · arXiv:2611.34848v1](https://arxiv.org/abs/2611.34848v1)

One explanation is that the models relied on the alignment supplied in the questions. A follow-up could hold the observed values and event descriptions fixed, vary event order, timestamps and alignment separately, and measure how often models notice incorrect matches. The results come from controlled interventions on these two tasks.

## Adding a generated image lowered average visual question-answering accuracy

Xueyang Yu and colleagues had a model describe a helper image and then answer the question using both the original and generated images. Across 13 pairs of vision-language models and image generators, the authors report that adding the generated image lowered mean accuracy by 3.7 percentage points, with declines on 9 of 10 tasks. On VSTAR, adding a generated image to the same planning hint also lowered accuracy. Repeated edits produced mixed results, and the authors report a three-percentage-point gain on ERQA after 10 edits. [Authors’ abstract · arXiv:2611.34935v1](https://arxiv.org/abs/2611.34935v1)

The VSTAR comparison holds the planning hint fixed so the effect of adding an image can be examined separately. A follow-up could use the same model and questions to compare the original image alone, the original with a text hint, and the original with both the same hint and a generated image. It could report the results for each task. The abstract’s results apply to the tested model pairs and tasks.

## Reverting one code block at a time tests which edits are needed

Aakash Goel and colleagues analysed 7,660 successful GitHub Copilot CLI runs with 18 models on SWE-bench Verified and DeepSWE. The study reverted each edit block from the final patch and reran the task tests to check whether the block was needed to pass. On SWE-bench Verified, the authors report that 11% of an agent patch’s code blocks on average were unnecessary for passing the task tests, and 89% of those blocks changed program behaviour. [Authors’ abstract · arXiv:2611.34875v1](https://arxiv.org/abs/2611.34875v1)

Passing the original task tests verifies only the behaviour those tests cover. A follow-up could rerun the task tests and an independent regression suite after each reversion to see whether apparently removable code affects other behaviour. The study analysed runs that solved tasks in the two benchmarks.
