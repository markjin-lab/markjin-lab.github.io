## 一、几条不变的原则
1. **只用免费服务。** 需要付费订阅、要登录或要中国手机号的来源（ctext API、知网、Tushare 等）都不接；返回验证页的来源（ctext 网页、OpenReview、Stooq）记为被拦并停源。
2. **与 XUANJI 完全隔离。** 采集 bot 不读 XUANJI 的任何数据、配置或密钥，也不把 markjin 的数据写过去；markjin 的数据只落在 markjin 自己的位置：公开部分在 markjin-data（新仓库），私有部分在本机私有记录或 markjin 的私有仓库（授权不允许转载的全文原件只放本机，见第五节）；不落到 XUANJI 的任何位置。
3. **原文可回放。** 稿件里的每句断言，都必须能回到 raw/ 中逐字节存档的一手原文（路线图第五节）。X、Grok、HN 这类内容只是线索，不能单独作为事实来源。例外（v0.11 修订提议，见第五节“含密钥 API 响应的存档”；该节生效前不适用）：响应里回显了访问密钥的 API 原件永久只私存，不进 raw/，也不公开任何去字段副本；这类数值只有在该机构的官方文件经书面授权逐字节存入 raw/ 并经 MANIFEST 登记之后，才可作论断依据；此前只作线索。
4. **不伪装、不绕过拦截。** 这是硬规则，见第四节。
5. **中医、佛学可以公开，但每一处都要注明原典出处**（书名、篇章或经号、卷、行，加公开链接）。中医不写诊断、处方或健康建议；佛学只写有原典出处的义理。两类稿件须 Codex 结论为 APPROVED，是否还须王总批准按路线图第三节的路由；不得自动批准（依据 t161u）。
6. **授权从严。** 条款没读到的，按“未读到”处理：可以私有存档，公开稿只用短引文加来源链接，不整段转载。

“实测”列的写法：通过表示返回了预期数据，且响应体已存档、在 TSV 中可查；部分可用表示连得上，但缺 key 或返回错误内容；被拦表示返回 403 或人机/JS 验证页，已停源、待人工复核；失败表示超时或连接失败；返回 200 但没存响应体，或样本里看不到预期内容的，写“结论待复核”。
“授权”列只写实际读到的条款内容；链接能打开、但没有逐条读的，写“条款未读到”；页面打不开的，注明状态码。

## 四、访问规则（硬规则）
1. **遵守各站的使用条款（ToS）和 robots.txt。** 条款或 robots 禁止自动访问的路径，不访问。
2. **不伪造 UA 或身份**（协调 bot 已定）。UA 如实写明 markjin 和站点地址；对方要求留联系方式的（如 SEC），只用王总确认过的邮箱：markjin 邮箱（quote_ref grok-bot:t177s858）。不伪造 Referer 或 cookie，不走代理，不轮换 IP，不用 headless 浏览器冒充真人。
3. **遇到登录、付费墙、验证码、JS 验证就停**（协调 bot 已定）。不尝试任何绕过手段；付费墙内容只记元数据和链接。
4. **一次 403 或一次验证，就停掉这个来源。** 采集 bot 记下状态码，把拦截页存档，此后不再请求该源，交人工复核。停掉的源，只有经人工批准才能复测，而且复测只发一次请求。10-11 统计局那次改过 UA、Referer 和 cookie 去重试，违反本条，以后不再这样做。
5. **请求频率**（王总已定，quote_ref grok-bot:t167s817）：公布了限速的来源，在其限速以内正常请求（如 arXiv 每 3 秒 1 次）；没有公布限速的来源可以请求，每个站点每分钟最多 1 次。两种情况遇到拦截都按第 4 条立即停源。
6. **阶段边界：新来源的一切请求都在王总确认进入路线图第十节第 2 阶段之后**（v0.10 例外：王总 2026-10-18 同意新数据机构提前开始候选试采，quote_ref Grok Bot 转达·2026-10-18 15:37 SGT；范围与条件照路线图 v1.12 第十节“新数据机构候选试采的例外”，只限这些机构的候选试采本身，本条其余内容不变）（依据路线图第十节与 Codex 审查意见；王总已定的五项管的是引文上限、全文保留、漏采率口径和请求频率，没有规定从哪个阶段开始接入新来源，本条与五项不冲突）。
   - 包括：统计局 RSS 与发布页的每日采集；统计局 403 替代路径的抓页；拿到 Semantic Scholar key、BEA UserID 后的复测；用 markjin 邮箱申请 Semantic Scholar key、BEA UserID（王总已确认，quote_ref grok-bot:t177s858，第 2 阶段起执行）；在王总 Mac 上对人民银行、海关、ECB 各测一次（王总已确认，quote_ref grok-bot:t177s858，第 2 阶段起执行）；SEC EDGAR 的复测（另须先过第 4 条停源人工复核）；第三节各表“存档方式”列写的一切抓取；对入选线索抓全文（例外见下）。
   - 不受影响：已是常规源的 arXiv、X，照现行采集流程和第 5 条频率执行。FRED 已停用（第九节）。
   - 入选线索抓全文的边界：第 1 阶段只请求下列白名单主机上该线索本身指向的那一页（如 arXiv 论文的 PDF/HTML、X 帖子本身），一次一页，遵守第 1–5 条，不借此做持续或批量采集。（v0.9，bot 补写，待王总确认；从严临时执行）
     - 主机名白名单（逐字完全相同才算匹配，不按域名后缀匹配，不区分大小写以外不做任何归一）：`arxiv.org`、`export.arxiv.org`、`x.com`。前三个按协调要求列入；arXiv 请求 URL 主机依据旧仓库（已归档）`raw/2026-10-10/`、`raw/2026-10-11/` 与 `raw/2026-10-11/round2/` 下 arXiv 的 query-log 登记，均为 export.arxiv.org（三份日志共 17 条，含 round2 的 5 条；其中 raw/2026-10-10 的 2 条为 http，其余 https）；X 走连接器，query-log 中没有直连主机。采集脚本本身不在 markjin-data 仓库内（scripts/ 只有 verify-raw.sh），以上依据只来自 query-log。原白名单中的 FRED 两个主机已随 FRED 停用删除（第九节）。
     - 不在白名单里的包括但不限于：arxiv.org 的其他子域（如 www.arxiv.org、info.arxiv.org）、stlouisfed.org 本身及其任何子域（含 fred、api、alfred、www，FRED 已停用）、t.co、pbs.twimg.com、twitter.com 及 x.com 的其他子域。
     - 跳转逐跳核对：遇到 HTTP 跳转（3xx Location）或页面内跳转时，不自动跟随；每一跳在发请求之前先核对目标主机是否在白名单内，在就继续，不在就停在这一跳：只记下该 URL 作线索，不对它发任何请求。例：x.com → t.co → 外站，停在 t.co，记下 t.co 的 URL，不请求 t.co，也不请求外站。实现上须关闭客户端的自动跟随（如 curl 不加 -L）。
     - 常规源链接到的其他站点页面（如 X 帖子 expanded_url 指向的外站文章），第 2 阶段起才抓；在此之前只记下 URL，当作线索，不请求该页。线索来自非常规源的，同样第 2 阶段起才抓。
   - 除路线图 v1.12 第十节明确列出的新数据机构候选试采例外外（停源复测和第八节前置步骤的限制不变），第 1 阶段（进化一期）对新来源一律不发请求，包括单次复测；10-11 的探测记录只作调研存档。

**含密钥 API 响应的存档（v0.11 修订提议：方案由 Grok Bot 2026-10-18 定，19:56 SGT 改定为不公开任何去字段副本，20:04 SGT 补充官方 Excel 的处理；经 Codex 审查通过后由 Grok Bot 报王总确认；王总确认并合并、且路线图中“私有存档的防篡改登记”的修订也已生效之后才生效，此前照本节最后一条过渡条款执行）**
- 适用范围：响应正文、响应头存档、query-log、PROVENANCE 或其他文件里出现访问密钥（API key、UserID、token 等）的来源。首例是 BEA 数据接口：它的 JSON 响应在 `.BEAAPI.Request.RequestParam` 里回显请求参数，其中 ParameterName 为 `USERID` 的那一项的 ParameterValue 就是 UserID。
- 原件：逐字节原响应永久只存本机私有目录（目录权限 0700，文件权限 0600）；不进 raw/，不进任何 git 仓库，不进审查 prompt 和审查日志。不生成用于存档或公开的去字段响应副本；私有核验只临时读取所需字段。按上文“私有存档的防篡改登记”在 MANIFEST 记一行（不写内容）。
- 可用的响应：只接受 HTTP 成功、恰有一个无重复键的完整 JSON 文档、没有机构定义的错误节点（BEA 为 `.BEAAPI.Error` 或 `.BEAAPI.Results.Error`），且登记的数据子树非空并含预期的表、行、期间和必要字段（BEA：`.BEAAPI.Results.Data`）。其余响应（非 JSON、空响应、多文档、重复键、解析失败、缺字段、错误响应）只作私有失败记录，不生成数值文件。重复键的检查不能只靠 jq，须用能报告重复键的解析器。
- 公开的只有三样：(1) 去掉 key 的请求地址，照现有 query-log 的做法（第九节），按 URL 参数结构剔除 `USERID` 和其他鉴权参数后再写；(2) 原件的 sha256（这是私有审查方核验用的记录，公众不能凭公开材料独立复算）；(3) 本项目从原件 `.BEAAPI.Results` 抽出的、未改动的数值及其出处（BEA 为 TableName、LineNumber、SeriesCode、LineDescription、TimePeriod、DataValue、CL_UNIT、UNIT_MULT、METRIC_NAME 与表注修订日，各字段照原样，不换算、不改写），附该机构要求的英文声明原句（BEA 见 6.2）。本轮数值文件只允许 T50305/B985RC、T50305/Y033RC、T11200/A053RC 三项，以及经明确批准后的 T11200/A051RC（见 6.2）；逐条核对表、SeriesCode、行号、期间和版本，重复、冲突或其他行一律不发布；其他指标另报王总批准。
- 派生文件标注：本项目制作的任何派生文件（如上面第 (3) 项的数值文件）都在文件开头写明“本项目制作，非 BEA 原件”（其他机构相应改为该机构名），并写明抽取所用的命令或脚本及其版本。公开数值文件存放在另经确认并登记的派生数据路径，不进 raw/；其 MANIFEST、PROVENANCE 记录标明“本项目制作，非 BEA 原件”，不得登记为机构官方原文。公开路径和登记格式经 Grok Bot 定并报王总确认之前，不发布数值文件。
- 公开核对：公开核对以该机构官网公开发布的官方文件为准，由读者自行到官网下载核对；公开时给出官方链接（BEA 为与所用表对应的官方整节 Excel，例如 T11200 所在的 https://apps.bea.gov/national/Release/XLS/Survey/Section1All_xls.xlsx、T50305 所在的 https://apps.bea.gov/national/Release/XLS/Survey/Section5All_xls.xlsx）。每条公开数值同时登记官方链接、所对应的数据版本（官方修订日）、工作表名和表行／期间的定位规则。本项目不存官方 Excel。试采中已取得的两份 BEA Excel 只作本机私有事件记录保留，逐份标记“未经授权请求所得、已弃用”，不作数据依据、正式存档或公开文件；以后如需本项目自己存一份官方 Excel，须另行取得书面授权，并在规划中带上该授权的引用。
- 论断依据：口径与数值以 API 原件为准。按第五节门禁第 1 条，私有原件和本项目的数值文件都不作论断依据；在按上一条取得书面授权、把官方文件逐字节存入公开 raw/ 并经 MANIFEST 登记之前，这些数值在日报中只作线索，不作论断依据。即使取得覆盖公开存档的书面授权，也须为每条拟用于论断的数值登记同版本官方文件的公开 raw/ 路径和 sha256、工作表、单元格或表行与期间，并按单位换算（6.2）逐值核对 API 原件、数值文件与官方文件；版本不一致、数值不符或无法定位的，仍只作线索。稿件断言指向该条登记。
- 不含密钥的检查（任何一项命中，或不能确认无凭据时，都停止发布或送审，报 Grok Bot）：对全部待发布文件（数值文件、响应头存档、query-log、PROVENANCE、MANIFEST）的内容、路径和文件名，提交说明与提交元数据，以及任何离开本机私有环境的片段、提示词和日志，检查凭据原值和实际用到的编码形式（URL 编码、JSON 转义）。检查只输出命中位置和次数，不输出凭据值。
- 审查方核验（每份数值文件发布前做一次）：审查与治理 bot 在本机私有环境里：(1) 复算原件 sha256，与公开记录一致；(2) 按“可用的响应”逐项检查；(3) 只读取原件的 `.BEAAPI.Results`，逐行比对数值文件每个字段的类型和值，确认未改动；(4) 按上一条做不含密钥的检查；(5) 签署核验记录：原件与数值文件的 sha256，解析器与 jq 版本，抽取命令或脚本版本，输出排序与编码规则，比对结果，核验人和签署时间，写进本机私有审查记录，供后来的审查方用保留的原件重跑。公开哈希写入 MANIFEST 和 PROVENANCE；Codex 结论摘要按路线图写入 approvals/codex/；review/ 只写其字段白名单允许的内容（白名单将在路线图 v1.12 中列入结论和 sha256）。送审只用经过不含密钥检查的数值清单。
- 密钥泄露：在任何共享位置、提交历史、公开仓库或日志里发现密钥值，立即停止使用旧凭据，向发钥机构办理撤销或禁用并取得失效确认；重新申请新 key 不等于旧凭据已失效，确认前停止相关取数与发布。已公开的文件先停止展示；涉及非 FRED 的 raw/ 删除，另按路线图取得撤回授权并登记，不援引第九节只适用于 81 个 FRED 路径的例外。记录只写发现日期和处理结果，不写密钥值。
- 公开能复核什么：公众可以复算数值文件的 sha256，到官网下载官方文件核对数值，也可以用自己的 key 向机构重新取数对照（机构可能已发布新版本）；不能凭公开材料复核私有 API 原件本身，这一点靠审查方的核验记录。
- 过渡条款：本节生效前，BEA 接口原件只私存；数值文件不公开，也不作日报论断的依据；本节生效前已取得的 BEA 原件只作核查材料，不进日报。

**为什么停用**
FRED 是圣路易斯联储办的经济数据汇集网站。它的法律条款在禁止事项第 (p) 条写明：未经该行事先书面同意，不得存储、缓存或存档 FRED 服务或内容的任何部分，也不得把 FRED 内容并入任何数据库、汇编、存档或缓存。条款还限制转载和再发布，并禁止把 FRED 服务或内容用于开发或训练软件系统和机器学习（含生成式 AI）。本规划要求原文逐字节存档、公开回放，与这些条款不相容。数据原本出自美国政府机构，但经 FRED 取得的副本同样受这些条款约束，所以改为直接从原始机构取数（第六节 6.1）。
